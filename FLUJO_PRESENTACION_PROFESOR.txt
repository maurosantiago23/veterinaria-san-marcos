BLOQUE 2: BASE DE DATOS ORACLE CLOUD Y MODELO 3FN (02:00 - 05:00)
--------------------------------------------------------------------------------
Accion en pantalla (Mauro):
En la Pestana 3 de GitHub abre la carpeta 'database' y hace clic en 'schema.sql'
(o muestra el diagrama DER en la documentacion).

Dice Gabriel:
"Para la base de datos implementamos Oracle Cloud Autonomous Database en la
region sa-valparaiso-1, estructurada en cinco tablas relacionales:
USUARIO para clientes, vendedores y administradores con claves cifradas;
CATEGORIA para alimentos, farmacia, accesorios y servicios medicos;
PRODUCTO para el catalogo de insumos y citas veterinarias;
BOLETA para el encabezado de ventas con folio y fecha;
y DETALLE_BOLETA para las lineas de cada compra.

En cuanto al modelo relacional, aplicamos Tercera Forma Normal: en DETALLE_BOLETA
guardamos el precio unitario y subtotal historico al momento de comprar. Si manana
un producto cambia de precio en la tabla PRODUCTO, las boletas historicas
conservan su valor contable original, eliminando dependencias transitivas.

Ademas, entre AWS EC2 y Oracle Cloud no usamos contrasenas en texto plano, sino
una conexion mTLS bidireccional mediante certificados con la Oracle Wallet."

BLOQUE 3: MICROSERVICIOS BACKEND SPRING BOOT Y SWAGGER (05:00 - 08:30)
--------------------------------------------------------------------------------
Accion en pantalla (Mauro):
Pasa a la Pestana 2 (Swagger UI en AWS EC2: http://<IP_EC2>:8080/swagger-ui/index.html).

Dice Mauro:
"En el backend organizamos los microservicios por dominio desacoplado dentro de
Spring Boot: productos, usuarios y ventas. Esto nos permite separar
responsabilidades limpiamente sin saturar la memoria de la maquina de AWS
levantando tres servidores Java separados.
Ahora vamos a probar los endpoints en vivo desde Swagger:"

Accion en pantalla (Mauro):
Abre GET /api/v1/productos, clic en 'Try it out' y 'Execute'.

Dice Mauro:
"Aqui ejecutamos el GET de productos. Como vemos, recibimos una respuesta 200 OK
con los datos directamente desde Oracle Cloud. Pueden notar que el sistema
diferencia productos fisicos como Simparica de servicios clinicos como Consulta
General, los cuales manejan cupos de atencion diaria."

Accion en pantalla (Mauro):
Abre POST /api/v1/auth/login, ingresa {"email": "admin@veterinaria.cl", "password": "1234"}
y presiona 'Execute'.

Dice Mauro:
"Ahora probamos la autenticacion. Enviamos las credenciales del administrador y
Spring Security nos responde con codigo 200 y el token JWT firmado, junto con el
rol ADMIN. Este token es el que viajara en cada peticion del frontend."

Accion en pantalla (Mauro):
Despliega POST /api/v1/boletas.

Dice Mauro:
"Y este es nuestro endpoint critico de ventas. En el codigo, BoletaService tiene
la anotacion @Transactional. Esto significa que la insercion de la boleta, el
guardado de cada linea de detalle y la rebaja de stock en la tabla PRODUCTO
forman una sola transaccion atomica. Si algun producto no tiene stock suficiente
o falla la base de datos a mitad de camino, Spring ejecuta un rollback automatico
total, garantizando que jamas quede una boleta a medias o inventario descuadrado."

Preguntas clave para Mauro:

- Arquitectura modular: Package-by-Feature para optimizar memoria en AWS EC2 frente a 3 JVMs.
